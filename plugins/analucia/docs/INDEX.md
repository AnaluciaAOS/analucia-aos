## Commands

Every command the owner runs ends with exactly one closing line: `OK: <what is now true>` on success, or the error with its `next` line (ORD-0041 part 6). Commands read by a program or a hook (`check-writeback`, `hook …`, `next`, `check-push`) print no such line.

- `aos validate [path] [--detail]` — any: check orders, verify files, director.lock, project.json and events.jsonl. The warnings that belong to a closed order are not printed: the closing line counts them (`… N warnings of closed orders not shown`) and `--detail` prints them; errors are always printed and the exit code is the same (ORD-0043 part 8)
- `aos event append --type <t> --actor <role> --subject <id> --payload <json>` — any: the low-level writer of the event log (prefer the lifecycle commands)
- `aos verify-log` — any: recompute the hash chain; names the first broken line
- `aos derive` — any: write .analucia/views/state.json and resume.md
- `aos history <ID>` — any: print the events of one record
- `aos run start ORD-NNNN` — executor: queued → active, run.started with the budget
- `aos run finish ORD-NNNN --outcome <o> --evidence <path>` — executor: run.finished + evidence; done → delivered. Outcome `parts_cap` (ORD-0043 part 18): the run did the parts a run may do (rule 6) and the order has more; it leads to queued like `budget_exhausted` and counts as an attempt; `budget_exhausted` keeps its meaning, the time of the run ran out
- The owner's gates at the end (ORD-0043 part 6): a document the owner must look at is asked with `aos review request` and the work goes on to `done`. `aos sign` shows all the reviews of one order together, right before its checks (the documents of an order that is not delivered come first); one decision of corrections (comment or reject) sends that order back for rework (`delivered → active`, written by the owner) without running its checks or touching the others. The executor starts its next run with `aos run start` (an active order with no open run: no second transition, same attempt budget), and `aos next` says so. `aos status` starts with one line of who waits for whom: `Waiting — owner N: sign <ID>, review <ID> · director N: … · executor N: start <ID>`
- `aos run handoff ORD-NNNN --next "<the part or step that comes next>"` — executor (ORD-0043 part 5): writes the handoff of the open run, `.analucia/views/handoff-<ID>.md` (generated, never committed): the run and its number, the minutes used and left, the last commit of the order, the files changed and not committed (names only) and the text of `--next`. `resume.md` carries it while the run is open; the `PreCompact` hook writes it by itself and keeps the `--next` a session wrote; `aos run finish` removes it
- `aos run take ORD-NNNN` — executor (ORD-0043 part 5): the calling session becomes the owner of the open run, recorded as `operation.logged` (`operation: run.take`, the run, the session, the former owner): no new run, no attempt consumed; the stop hook follows the new owner. A session declared director cannot take a run (`E_DIRECTOR_RUN`); with no open run it refuses with the line of `aos next`. `aos next` tells an executor session that is not the owner to read the handoff and take the run
- The closing outcome (ORD-0043 part 4): the report carries one fixed line just above its outcome, `Work: complete` or `Work: not complete`. `aos run finish` refuses `blocked` and `needs_decision` when the report says `Work: complete` (`E_WORK_COMPLETE`: finish `done`; the owner's review is asked with `aos review request` and decided at the signature); a report without the line is accepted with one line of warning. `aos sign` prints one line for each blocked order: what it waits for and the command that takes it out; it offers nothing to close for it, blocked/needs_decision → blocked, budget_exhausted/failed → queued
- `aos verify ORD-NNNN` — system (director runs it): director lock + verify-file checks; delivered → verified. Every check runs once at every risk level; for `risk: high` a check that fails is run again, once, and its second result counts: the evidence shows both runs, records `"samples": 1` and the names of the repeated checks, and marks a check that passed on the second run (ORD-0043 part 17)
- Checks of form (ORD-0043 part 2): a check of a verify file may carry `"class": "form"` (a trailer on an evidence-only commit, a label of the report, the name of the signing branch); without the key it is a check of substance. `aos validate` refuses the class form on a check that runs the test suite, `verify-log`, `validate`, `check-roles` or the release guard (`E_FORM_CLASS`). `aos verify` runs every check and reports the failed ones in two groups (`FAIL [form] …`). In `aos sign`, when every failed check of a delivered order is of class form, the owner may waive each one with the typed word `WAIVE` and a written reason of at least 10 characters: the waivers are recorded in `owner.signed` (`payload.waived`) and in the verify evidence (`WAIVED: …`), and the order goes on to verified and closed. `aos status <ID>` and the queue view show `waived: N`. An agent never waives (`E_OWNER_TTY`); a check of substance is never waived
- Verify files (director): a check never ends a git diff/log range at a moving ref (HEAD, a branch, origin/…); use a commit SHA or `{order_commit}`, which `aos verify` resolves to the newest commit with the trailer `Analucia-Order: ORD-NNNN` (E_MOVING_REF, E_NO_ORDER_COMMIT; ORD-0034). Template: `templates/verify-file.example.json`.
- `aos close ORD-NNNN [ORD-…]` — owner, own TTY: verified → closed after typing CLOSE
- `aos close ORD-NNNN --as director` — director, risk: low only: verified → closed without a TTY (SPEC-0003 §4)
- `aos ask open ASK-NNNN` — director: record.created + ask.opened for a locked .analucia/asks/ASK-NNNN.md (SPEC-0004 §1)
- `aos ceo export [--out <path>] [--locale en|es]` — any: write the owner sheet (.xlsx): How to use, Asks, Orders, States (SPEC-0004 §2)
- `aos ceo import [<path>]` — owner, own TTY (without a path it is asked in the window: IMPORTAR): record the sheet: ask decisions and close sign-offs, after typing CONFIRM; all-or-nothing
- `aos init [--locale en|pt|zh-Hans|hi|es] [--answers <file> [--dry-run]]` — owner, own TTY (dry run: anyone): guided onboarding: three moments, safe defaults, then the configuration of SPEC-0005 §4 after CONFIRM
- `aos init --hosting managed|own-server|"already: <where>"|later [--dry-run]` — owner, own TTY (dry run: anyone): change only the hosting answer: project.json hosting, a hosting.chosen event; the plan shows the dated cost table (AMD-0006)
- `aos init --check` — any: the setup checks of SPEC-0005 §5 (PASS/WARN/FAIL, each WARN/FAIL with next); records the inventory; saves .analucia/views/onboarding.md; exit 1 on any FAIL
- `aos permissions write [--local]` — owner or director: write .claude/settings.json: permission profile (allow a `git push` that names a branch that is not protected; ask for a push that names a protected branch or no branch; deny force push) and the plugin enabled for this repo (SPEC-0004 §3, §7; ORD-0043 part 16). With `--local` it writes the permission rules only, to `.claude/settings.local.json`, which git ignores (AMD-0017 section 2)
- `aos role declare director --scope "<paths>"` — director: role.declared with the director write scope (SPEC-0004 §6)
- `aos admit ORD-NNNN` — director: lists the open orders (addendum before new order, AMD-0007 §4), then record.created with version pins, draft → ready → queued (SPEC-0003 §5)
- `aos cost record --usd <n> --source "<text>" [--order ORD-NNNN] [--month YYYY-MM]` — director (or owner): log a cost; threshold alerts at 50/80/100% inform the owner and never block
- `aos cost status [--month YYYY-MM]` — any: budget, spend, percent, alerts and cost per closed order
- `aos halt --reason "<text>" / aos resume` — owner, own TTY: the off switch (.analucia/HALT); without --reason, at a terminal, the reason is asked in the window (DETENER)
- `aos status` — any: one line per order that is not closed: its stage in the owner's words, who holds it (with the session name when known), why it is stopped and since when; `aos status <ID>`: the detail of one, with the single next step (the line of `aos next`) or, for a closed order, how long each stage took; ends with `OK: …` (ORD-0042 part 6)
- `aos status <ID> --chain [--json]` — any: the chain of an order with the time of each link: decision → placed → admitted → each run → its evidence → its outcome → verified → signed; `--json` prints one array of `{"link", "ts"}` with the link names `decision`, `placed`, `admitted`, `run`, `evidence`, `outcome`, `verified`, `signed`
- `aos status --metric` — any: for each order that has a recorded decision, the minutes from `decision.recorded` to the first `run.started` and the number of owner steps in between (target 1), measured from the log; an order with no recorded decision says so; the queue view shows it
- Consumption per order (ORD-0042 part 11): a hook receives no token or cost figure, so `aos status --metric` and `aos status <ID>` show what the log knows for each order — sessions, runs and the minutes of its finished runs — and say that tokens are not known
- `aos decision record --text "<one line>" [--source <file>] --order <ID> [--order <ID> …]` — director: the event `decision.recorded` (the owner's decision that the orders carry out). The owner's own placement records it by itself when the draft carries the key `decision:`
- `aos repair-log` — owner, own TTY (launcher REPARAR), typed word REPAIR: repairs the event log only when the log does not verify, the version in the last commit verifies, and every line after that committed version is a session line (session.start, session.end, role.declared); it puts back the committed version, keeps the removed lines under .analucia/views/log-removed-<time>.jsonl and records one operation.logged event; in every other case it changes nothing (E_LOG_NOT_REPAIRABLE: the director restores). The one exception to "the log is never rewritten" (ORD-0042 part 4)
- `aos check-writeback` on `PreCompact` — never blocks (ORD-0043 part 1): compacting does not end a run. With a run open in that session it exits 0, says in one line which order has a run open and writes the handoff `.analucia/views/handoff-<ID>.md`; a broken log only warns
- `aos check-writeback` — hook (Stop): exit 2 while the chain is broken, or while a run is open that this session owns (`run.started` records the session that started it; another session, and a session that declared the role director, end freely and are told which order has a run open; with no session in the hook input, or a run with no recorded owner, every session is blocked; ORD-0041 part 5)
- `aos hook session-start` — hook (SessionStart): derive, print resume.md, record role.declared and session.start
- `aos hook user-prompt` also obeys the owner's words (ORD-0043 part 15): a prompt that is only `STOP`, `ALTO`, `DETENER` or `PARA` (any case, punctuation around it allowed) halts the project through the same function as `aos halt` (reason "the owner said <word> in the session <name>"); a longer prompt that starts with one of them is an ordinary prompt (no halt, no record, no context; AMD-0019); a prompt that is only `AVANZA` is recorded and the session is told to run `aos next`. The record (`operation.logged`, `owner.word`) carries the word, the session and the time, never the prompt. `aos resume` stays owner only
- `aos hook pre-tool-use` — hook (PreToolUse): block tools under HALT and writes to protected paths; for every role, a write or a delete inside the `.analucia/` folder of another project (any `.analucia/` that is not under this project's root) is refused with `E_OTHER_PROJECT`: open a session in that project. Reading stays free (ORD-0043 part 10)
- `aos agents-md sync` — any: refresh only the analucia block of AGENTS.md
- `aos check-roles` — any: one analucia block; CLAUDE.md is @AGENTS.md
- `aos check-push [remote] [url]` — git pre-push hook (inside an agent session it also refuses a protected branch as destination, E_PROTECTED_PUSH, ORD-0043 part 16): remote user and credential user = github_owner; no credential in the URL; every pushed commit outside owner/director paths carries Analucia-Order; no secret pattern in added lines; no commit that carries the trailer of an order and is dated after the last run.finished of that order while no run of it is open (E_COMMIT_AFTER_FINISH, ORD-0041 part 8)
- `aos install-git-hooks` — owner or director: set core.hooksPath to .githooks (pre-push), and write in the repository's own git configuration the user of the remote URL and the credential user for the account of each remote (`github_owner`, or `push_accounts.<remote>` in project.json for a remote of another account); never the global configuration, never a credential. `aos init` does the same. Every preflight includes the built-in check "push account" (ORD-0042 part 5). The hook names no plugin version: a copy of the plugin inside the repository is named by its path; an installed copy is found at each push, the newest one, as the launchers do. Every preflight also includes, for the same remotes, the built-in check "push guard installed": the hook exists where git looks for it (`core.hooksPath` honoured), it calls `aos check-push`, and no line of it carries a version number; a failure names this command and consumes no attempt (ORD-0043 part 12)
- `aos trailer check <order ID> --from <commit>` — any (verify files; ORD-0043 part 12): every commit after `<commit>`, up to the newest commit of the order, that changes code carries the trailer of the order; a commit that touches only the log, the evidence or the director paths needs none. It calls the same function as `aos check-push` (one trailer rule); exit 1 with the commits that fail. A verify file uses it instead of a check written by hand
- `aos eval run` — any: deterministic evaluations of the mechanisms (no model calls): PASS/FAIL per scenario, .analucia/views/evals.md, an eval.run event; exit 0 only if all pass
- `aos adopt [--locale en|es|pt|zh-Hans|hi]` — owner or director: read-only adoption audit (SPEC-0006): findings, not verified, proposed orders in .analucia/views/adoption.md; one adoption.audited event; exit 0 / 1 (high) / 2 (cannot run); never shows a secret
- `aos metrics first-hour` — any: the owner first hour from the log only (AMD-0004): started, first_closed, elapsed, status; refreshes .analucia/views/first-hour.md (also written by aos derive)
- `aos pause ORD-NNNN --reason "<why>"` — executor: close the open run as blocked and move active -> paused (AMD-0005 §2)
- `aos resume-order ORD-NNNN --reason "<why the block has ended>"` (also `aos unblock ORD-NNNN --reason "…"`) — executor (ORD-0043 part 3): blocked -> active when neither automatic condition holds (the owner did what the order waited for and nothing in the log says so): the transition the state table allows, with the reason, and the next run, within the attempt budget and after the preflight. Without `--reason` it refuses and gives this line. `aos next` names the line for a blocked order. Nobody writes that transition with `aos event append`
- `aos resume-order ORD-NNNN` — executor: paused -> active with a new run, within the attempt budget; also blocked -> active when the block has ended (an amendment to the order was recorded after the block, or the ask it waited for was resolved): nobody writes that transition by hand (ORD-0042 part 2)
- `aos sign` — owner, own TTY: draft orders waiting to be placed first (PLACE; ORD-0040), then documents waiting for review (approve, comment, reject, open; AMD-0007), then verify every delivered order, show results and evidence, close what passed after typing CLOSE, record owner.signed, commit and push the sign-off (AMD-0005 §3)
- Step to main (ORD-0041 part 7, AMD-0015 §7): when `aos sign` closed at least one order on a branch that is not the default branch and its sign-off is pushed, it shows the branch, the number of commits and that it will be a fast-forward, and asks for the typed word `MERGE`; then it switches to the default branch, merges fast-forward only and pushes through the guard. If a fast-forward is not possible or a step fails, it changes nothing further and says so. Never a force, never a merge commit, never from an agent
- `aos sign --install-launcher` — owner: write FIRMAR.cmd and FIRMAR.sh in the project root: double-click to sign
- `aos next` also covers (ORD-0042 part 2): a queued order whose last recorded preflight failed (the director is told, with the evidence file) and a blocked order whose block has ended (the executor gets `aos resume-order`). With no instruction, an executor runs `aos next` and does what it says
- `aos next` — any: exactly one line: the single thing that comes next and who does it, in the project language, with the click or the command as it exists on this machine; works in a folder with no .analucia/; writes nothing; the SessionStart hook shows the same line (ORD-0040)
- `aos scratch add <ID> --path <folder> [--pid <n>]` — executor (ORD-0043 part 9): records, in `.analucia/evidence/<ID>/scratch.json`, a folder that holds a copy of real data and the process that serves it: names and numbers only, never content. `aos scratch check <ID>` — any (meant for verify files): exit 0 when every recorded folder is gone and every recorded process has ended (or nothing was recorded: one line), exit 1 with the list otherwise. `aos run finish --outcome done` calls the same function and refuses while a copy remains (`E_SCRATCH_REMAINS`); other outcomes are not held. An order that copies real data lists the backups that are kept and the ones that may be deleted; nothing else is deleted
- `aos update` — any role, an agent included (ORD-0043 part 7; launcher ACTUALIZAR): updates the marketplace the installed plugin came from and then the plugin, in every scope where it is installed, through the `claude` command-line tool (found on the PATH or in its usual places; `CLAUDE_CONFIG_DIR` is honoured). It prints the version before and after for each installation and ends with one closing line; when the tool is not found or asks for a sign-in it changes nothing and says exactly that. It never edits a file of the configuration folder. `aos next` (on stderr) and the SessionStart line warn in one line, never a block, when the installed plugin is older than the newest version the machine can see without the network: the marketplace copy next to the installation, or the plugin source a project carries. The private repository names its marketplace `analucia-aos-private`; the public tree keeps `analucia-aos` (`scripts/build-public-tree.mjs` writes that name)
- `aos launchers install` — any role, an agent included (files only): write the owner click launchers INICIAR (`aos init`), FIRMAR (`aos sign`), DETENER (`aos halt`), REANUDAR (`aos resume`) and IMPORTAR (`aos ceo import`) as .cmd and .sh in the project root; each finds the plugin through CLAUDE_CONFIG_DIR and takes the installed version by numeric order (ORD-0040)
- `aos preflight <order ID>` — any: run the `preflight` checks of the order's verify file (same shape as `checks`, meant to pass on the untouched tree) for a placed order or a draft; prints each result and one final line, writes its output under the order's evidence folder, changes no state. `aos admit` runs it and refuses when a check fails; `aos run start` runs it again and then starts nothing: no run.started, no attempt consumed (E_PREFLIGHT_FAILED; ORD-0041 part 4, AMD-0015 §4)
- Business rules (ORD-0042 part 10): the body section `## Business rules` of an order, one rule per list item with one example with numbers (`- none` when there is none). `aos drafts` checks its shape and asks for it in a draft of kind build; `aos sign` prints the rules before the typed `PLACE`; the placement records them in `decision.recorded`
- Report lines (ORD-0043 part 13): a verify file may carry the top-level key `report_lines`, a list of `{"name": "…", "pattern": "<regular expression of one line>"}`: the lines the report of the order must carry. `aos verify` checks each one against `.analucia/evidence/<ID>/report.md` as a check of class form (`report line: <name>`). `aos run finish --outcome done` refuses while one is missing (`E_REPORT_LINES`): the run stays open and no attempt is consumed; any other outcome is not held
- `aos report template <order ID>` — any: prints the skeleton of the report (`templates/report.md`) with the fixed sections and one line to fill per entry of `report_lines`
- `aos report check <order ID>` — any (verify files): tries only the lines of `report_lines` and the fixed sections (`## Evidencia`, the `Work:` line, the last line `OUTCOME:`) on the report as it is; changes no state; exit 1 with what is missing
- Owner data (ORD-0043 part 14): `project.json` may carry `owner_data`, a list of path patterns (relative to the project root; `*` stops at a slash, `**` does not, a pattern with no slash names a file at any depth) of the files only the owner writes. `aos init` asks for them once (empty by default). The PreToolUse hook refuses, for every agent role, a write or a delete on a path that matches (`E_OWNER_DATA`); reading stays free
- `aos tracked <path> [<path> …]` — any (ORD-0043 part 14): one line per path, from `git ls-files` and `git check-ignore`: "under version control", "ignored by the rule \"<rule>\" of <file>:<line>" or "neither". Quote its line before stating that a file is or is not under version control
- `aos replaced check <order ID>` — any (verify files): at the newest commit of the order, every path of its `replaces:` list no longer exists; exit 1 with the list of what is still there; exit 0 and one line with no key or an empty list. `aos drafts` asks for the key in a draft of kind build (ORD-0042 part 7)
- `aos docs check <order ID>` — any (verify files): for the commits of that order, every file added inside a folder of earlier records of the project must be named, by its path, in the order or one of its amendments; exit 1 with the list; exit 0 and one line when the project has no such folder (ORD-0041 part 2, AMD-0015 §3)
- Earlier records (ORD-0041 part 2): `aos adopt` lists the folders of earlier orders, reports and decisions of the project (by folder and file names only, with counts and the numbering found) under their own heading; an order may carry `continues:`, free text naming the earlier record it continues, shown next to its ID in the queue, in `aos next` and in the owner sheet
- `aos ids` — any: the map of record IDs for people: each existing record, its ID and the same number under the project code (nothing is renamed), and the next free ID of each kind; one line when the project has no code yet (ORD-0041 part 1)
- Project code (ORD-0041 part 1, AMD-0015): `project_code` in project.json, 2 to 5 capital letters, never a type word, chosen by the owner at `aos init` and unique on the computer (list in the configuration folder, `CLAUDE_CONFIG_DIR` honoured). New records are `<CODE>-NNNN`, `<CODE>-AMD-NNNN`, `<CODE>-ASK-NNNN`; every existing ID stays valid; a new record with the old prefix is refused (E_ID_PREFIX)
- `aos drafts` — any: the draft orders in .analucia/drafts/ (ORD-NNNN.md with its verify file ORD-NNNN.json), whether each can be placed and why not, and the next free ID; exit 1 while one is not ready. The owner places the ready ones in `aos sign` by typing PLACE: the tool copies them to the protected paths, writes their hashes in director.lock and admits them (ORD-0040)
- `aos review request <path> --order ORD-NNNN` — executor: register a document (plan, design, mockup) for the owner: review.requested with its sha256 (AMD-0007 §1)
- `aos workflow check ORD-NNNN` — any (verify files): exit 0 when design.md and plan.md of a workflow: qrspi order have a current approve (AMD-0007 §3)
- `aos hook user-prompt` — hook (UserPromptSubmit): names the session as `aos hook session-name` does and, never blocking the prompt, adds one line of context when the prompt is for another project: it names a record that carries the code of another project of this computer, a record that does not exist in this project, or it starts with `Project: <name>` and the name is neither the code nor the folder name of this project (ORD-0042 part 8)
- `aos hook session-name` — hook (SessionStart, UserPromptSubmit): names the session by its role without the user doing it: `DIRECTOR <project code or folder name>` for a session that declared that role (ORD-0043 part 10: one director per project), `EJECUTOR <project code or folder name>` otherwise (hook output `sessionTitle`); a name a person gave is never replaced; it writes nothing. The session of an outside advisor is named by hand `DT <topic>` (ORD-0041 part 3)
- `aos hook session-end` — hook (SessionEnd): session.end with the session id and reason; never blocks (AMD-0007 §2)
- `aos backup [--remote origin]` — executor or owner: push a snapshot of the working tree (uncommitted and untracked, not ignored) to backup/<YYYY-MM-DD>; never touches the branch, index, tree or main; refuses on a secret (ORD-0024)
- `aos backup --restore-hint` — any: the latest backup branch and the commands to restore it in a new folder
- `aos explain <CODE>` — any: print the page of an error code
