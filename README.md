# analucia-aos

Analucia AOS is a loop for software work: the owner decides, sees everything and signs; an AI coding agent builds. Each piece of work is a typed **order** with acceptance checks. The agent executes it and attaches evidence, and every step is recorded in an append-only, hash-chained event log.

## The three steps

1. **You decide.** The director (a supervisor agent working for you) writes an order in `.analucia/orders/ORD-NNNN.md`: what to build, its checks in `.analucia/verify/ORD-NNNN.json`, and its risk (`low`, `medium` or `high`).
2. **The agent builds, with evidence.** The executor runs one order at a time, inside its scope, and writes `.analucia/evidence/ORD-NNNN/report.md` with the raw output of each check. It cannot edit orders, verify files or specs, and it cannot verify or close its own work.
3. **You sign.** `aos verify` runs the checks again. You look at the result and the evidence, and you close the order with `aos sign` at your own terminal. Only `low` risk orders may be closed by the director.

## Install

It is a plugin for Claude Code. The marketplace is `analucia-aos` (`.claude-plugin/marketplace.json`), and its plugin `analucia` lives in `plugins/analucia/`. In the folder of your project:

```
claude plugin marketplace add AnaluciaAOS/analucia-aos
claude plugin install analucia@analucia-aos --scope project
```

Claude Code applies a repository's settings only after you accept the workspace trust dialog.

## A first session

1. Open a new Claude Code session in the project folder. The first context is the project summary from the `SessionStart` hook (generated by `aos derive`, never committed), and it starts with `Status: …`. Run `/hooks`: it lists `SessionStart`, `Stop`, `PreCompact` and `PreToolUse` from the plugin (analucia).
2. In your own terminal, run the guided start: `aos init` (three short moments, safe defaults, then `CONFIRM`), and later `aos init --check` to see the setup checks. The commands are written `aos <command>` here. In this repository that means `node plugins/analucia/bin/aos.mjs <command>`. In another project, run the same `aos.mjs` from the folder where Claude Code installed the plugin.
3. A project already under way (more than 20 commits or 50 tracked files, SPEC-0006 §3) gets a read-only audit first (`aos adopt`): findings, what could not be checked, and proposed orders.
4. The director writes and admits the first order. The executor runs it (`aos run start` → work → evidence → `aos run finish`), and you sign it with `aos sign`.

All commands, error pages and spec versions are listed in [`plugins/analucia/docs/INDEX.md`](plugins/analucia/docs/INDEX.md). Every error prints `next (<who>): …`, and `aos explain <CODE>` shows its page.

## Honest limits

- It is a Claude Code plugin. Its guards (hooks) run inside Claude Code sessions, and other coding agents are not covered.
- The checks are only as good as the verify files. `aos verify` runs the commands that were written; it does not judge what nobody wrote down.
- The tool never connects to a server. The own-server checklist (`plugins/analucia/docs/hosting/VPS-CHECKLIST.md`) is text for the owner.
- The adoption audit is read only. It reports what it could not check as `not_verified`, never as clean. A secret is reported by kind, file and line, never by value, and only the owner can rotate it at the provider.
- The secret scan knows a fixed list of patterns (`plugins/analucia/core/secret-patterns.json`); anything else is not found.
- Signing, halting and resuming need the owner at their own terminal.
- The Portuguese, Simplified Chinese and Hindi texts are marked `reviewed: false`.

## The plugin governs this repository

`.claude/settings.json` (written by `aos permissions write`) declares this repository's marketplace and enables the plugin for every session opened here. It holds the permission profile too: edits inside the repo, `node`, and read-only `git` and shell commands are allowed. `git push` asks. Force pushes, `git reset --hard`, `rm -rf` and reading `.env`, `.env.*`, `*.pem` and `*.key` are denied. Your personal local settings file in `.claude/` stays untracked and is never touched.

To turn it off: `claude plugin disable analucia@analucia-aos --scope project`, or follow `.analucia/rollback/ORD-0010.md`.

## Release guard

`scripts/release-guard.mjs` checks that no denylisted term appears in any git-tracked file:

```
node scripts/release-guard.mjs <denylist-file>
```

Exit 0 = clean, 1 = matches found (printed as `file:line:term`), 2 = denylist missing (fail closed).
